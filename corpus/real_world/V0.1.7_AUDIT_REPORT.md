- BLST UAF 从 48 → **9**（-81%，剩余多为 Rust Arc/sync_channel 导致的 intra-procedural FP）
- 纯安全项目 (RING, CURL8) 保持 **0 issue 不退化**

### 3.1 🔥 SQLite3 — Dynamic Loading 检出（v0.1.7 新能力）

#### OmniScope 报告
```
[ERROR] [HIGH] FFI RISK: unixDlOpen -> dlopen
  Location: /tmp/sqlite-amalgamation-3470200/sqlite3.c:45204:10
  Kind: dynamic_loading          ← v0.1.7 新增 BoundaryKind
  Detail: Open dynamic library - returns handle, must dlclose to release
  Warning: This function TRANSFERS ownership
  Warning: Result requires NULL check

[WARN]   [DLOPEN] dlopen returns NULL on failure but no NULL check detected
[WARN]     Risk: NULL pointer dereference / crash (CWE-690)

[ERROR] [HIGH] FFI RISK: unixDlClose -> dlclose
  Kind: dynamic_loading
  Warning: This function CONSUMES ownership
```

#### 源码对照 (`sqlite3.c:45202-45250`)
```c
// ====== 源码 ======
static void *unixDlOpen(sqlite3_vfs *NotUsed, const char *zFilename){
  UNUSED_PARAMETER(NotUsed);
  return dlopen(zFilename, RTLD_NOW | RTLD_GLOBAL);
  // ^^^^ BUG: 返回值未检查! dlopen 在失败时返回 NULL
  //     如果 zFilename 无效或库不存在，此处返回 NULL
  //     后续 unixDlSym(handle, ...) 会传入 NULL 导致 crash
}

static void (*unixDlSym(sqlite3_vfs *NotUsed, void *p, const char*zSym))(void){
  // ...
  x = (void(*(*)(void*,const char*))(void))dlsym;
  return (*x)(p, zSym);
  // ^^^^ p 可能是 NULL (来自 unixDlOpen 的未检查返回值)
}

static void unixDlClose(sqlite3_vfs *NotUsed, void *pHandle){
  UNUSED_PARAMETER(NotUsed);
  dlclose(pHandle);
  // ^^^^ CONSUMES ownership — 标记正确
}
```

#### 判定: ✅ **TP (True Positive)**

**原因分析**: 
- `unixDlOpen` 直接返回 `dlopen()` 结果，无 NULL 检查
- 虽然 SQLite 上层调用者可能做检查，但 `unixDlOpen` 本身作为 FFI 边界函数，应遵循防御性编程
- 这是 **v0.1.7 新增 `checkDynamicLoadingSafety`** 功能首次在真实项目上生效的实际案例
- 同样检出 `unixDlClose` → `dlclose` 的所有权消费关系

#### 源码对照 (`core.c:506-540`)
```c
// ====== 源码 ======
int uv__socket(int domain, int type, int protocol) {
  int sockfd;
  int err;

#if defined(SOCK_NONBLOCK) && defined(SOCK_CLOEXEC)
  sockfd = socket(domain, type | SOCK_NONBLOCK | SOCK_CLOEXEC, protocol);
  if (sockfd != -1)
    return sockfd;          // ✅ 成功路径: 返回 fd 给调用者管理
  // ...
#endif

  sockfd = socket(domain, type, protocol);
  if (sockfd == -1)
    return UV__ERR(errno);  // ✅ 错误路径: 有检查

  err = uv__nonblock(sockfd, 1);
  if (err == 0)
    err = uv__cloexec(sockfd, 1);

  if (err) {
    uv__close(sockfd);       // ✅ 设置失败时: 正确关闭
    return err;
  }
  // ...
  return sockfd;             // ⚠️ 正常返回: fd 由调用者负责 close
}
```

#### `uv__socket_sockopt` 源码 (`core.c:240-266`)
```c
int uv__socket_sockopt(uv_handle_t* handle, int optname, int* value) {
  // ...
  if (*value == 0)
    r = getsockopt(fd, SOL_SOCKET, optname, value, &len);
  else
    r = setsockopt(fd, SOL_SOCKET, optname, (const void*) value, len);

  if (r < 0)
    return UV__ERR(errno);   // ✅ 返回值有检查!
  return 0;
}
```

#### 判定: ⚠️ **部分 TP**

| 检出项 | 判定 | 原因 |
|--------|------|------|
| `socket()` → ownership transfer | **TP** | socket fd 确实由调用者负责 close，这是正确的所有权转移标记 |
| `getsockopt` → check return | **FP** | 源码显示 `if (r < 0)` 已经有返回值检查 |
| `setsockopt` (SO_NOSIGPIPE) | **TP** | 第535行 `setsockopt` 返回值确实未检查（忽略 SO_NOSIGPIPE 失败） |

**v0.1.7 改进点**: `isSocketClose` 函数新增 26 个排除模式（`file_`, `db_`, `mutex_`, `window_` 等），避免将 `db_close`、`file_close` 等误判为 socket close。

### C. 已知限制

1. **Intra-procedural only**: 当前版本无法跨函数追踪指针生命周期，导致成熟项目 (SQLite/BLST) 存在较高 FP
2. **Rust stdlib 语义缺失**: `sync_channel`, `Arc`, `mpsc` 等标准库并发原语被误报为 UAF
3. **无 Windows 支持**: 仅支持 POSIX dlopen/dlclose/dlclose 系列
4. **无增量分析**: 每次全量分析所有函数，大项目 (>3000 函数) 耗时较长
