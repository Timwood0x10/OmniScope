### 2.1 Dynamic Loading (dlopen/dlsym/dlclose) — 🆕 v0.1.7

**检测范围**: `dlopen`, `dlclose`, `dlsym`, `dlerror` 系列函数

**检出能力**:
```
✅ dlopen 返回值 NULL 检查缺失     → [DLOPEN] 警告
✅ dlsym 返回值 NULL 检查缺失     → [DLOPEN] 警告
✅ dlclose 所有权消费标记           → FFI RISK: CONSUMES ownership
✅ dlsym 派生指针追踪             → dlclose 后使用 dlsym 结果 = RESOURCE-UAF
✅ CONTRACT VIOLATION              → nullable pointer 未检查警告
```

[ERROR] [LOW] FFI RISK: uv__socket -> setsockopt

**源码对照** (`libuv/src/unix/core.c:506-540`):
```c
int uv__socket(int domain, int type, int protocol) {
  int sockfd;
#if defined(SOCK_NONBLOCK) && defined(SOCK_CLOEXEC)
  sockfd = socket(domain, type | SOCK_NONBLOCK | SOCK_CLOEXEC, protocol);
  if (sockfd != -1)
    return sockfd;           // ✅ 成功路径: fd 给调用者
#endif
  sockfd = socket(domain, type, protocol);
  if (sockfd == -1)
    return UV__ERR(errno);   // ✅ 错误路径: 有检查
  err = uv__nonblock(sockfd, 1);
  if (err == 0)
    err = uv__cloexec(sockfd, 1);
  if (err) {
    uv__close(sockfd);       // ✅ 失败时 close
    return err;
  }
  // ...
  setsockopt(sockfd, SOL_SOCKET, SO_NOSIGPIPE, &on, sizeof(on));
  // ^^^^ TP! setsockopt 返回值未检查 (忽略 SO_NOSIGPIPE 失败)
  return sockfd;
}
```

**判定**: ⚠️ **部分 TP**
- `socket()` ownership transfer → **TP** (设计如此，fd 由调用者 close)
- `setsockopt(SO_NOSIGPIPE)` 未检查返回值 → **TP** (真实 bug pattern)
- `getsockopt` → **FP** (源码有 `if (r < 0)` 检查)

## 七、附录

### A. FFI/Unsafe 检测范围定义

OmniScope 将以下内容归类为 **FFI/Unsafe 专项检测** (>80% 权重):

| 类别 | 说明 | 示例 |
|------|------|------|
| **Dynamic Loading** | 动态库加载/符号查找/卸载 | dlopen, dlsym, dlclose, LoadLibrary |
| **Thread Management** | 线程/互斥锁/信号/进程创建 | pthread_create, fork, signal, sigaction |
| **Network I/O** | Socket/网络操作 | socket, connect, bind, getsockopt, setsockopt |
| **Allocator/Deallocator** | FFI 内存分配/释放 (非标准 malloc/free) | EVP_*_new, BIO_*, RSA_*, SSL_*, X509_* |
| **JNI/Java FFI** | Java Native Interface | FindClass, CallVoidMethod, NewGlobalRef |
| **Python C API** | Python 扩展开发 | PyArg_ParseTuple, PyObject_Call, PyGILState_* |
| **Process Management** | 进程控制 | execvp, system, popen |
| **Callback Escape** | 回调函数逃逸 (跨语言) | pthread_create fn_ptr, signal handler |

以下归类为 **通用分析** (<20% 权重):
- malloc/free 配对 (标准 C 内存)
- buffer overflow (栈/堆)
- format string vulnerability
- ownership transfer (纯 C/C++ 对象)
- dead code / unreachable
