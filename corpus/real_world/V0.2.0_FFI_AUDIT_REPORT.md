## 三、技术实现

### 3.1 单次扫描跨函数追踪架构

**设计原则**: 一次扫描同时建立调用图和内存关系图

```
┌─────────────────────────────────────────────────────────────┐
│ 单次扫描 (Single Pass)                                     │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐ │
│  │  CallGraph   │    │MemoryRelations│    │ FuncAnalysis │ │
│  │  func→calls[]│    │ ptr→origin   │    │  freed_ptrs │ │
│  └──────────────┘    └──────────────┘    └──────────────┘ │
│         │                   │                   │          │
│         └───────────────────┴───────────────────┘          │
│                         │                                   │
│              跨函数分析: resolveFreeValidation()            │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 核心数据结构

**MemoryRelations** ([src/semantics/memory\_relations.zig](src/semantics/memory_relations.zig)):

```zig
pub const MemoryRelations = struct {
    call_graph: std.StringHashMap(std.ArrayList([]const u8)),
    origins: std.AutoHashMap(u64, PointerOrigin),  // ptr → alloc func
    func_allocs: std.StringHashMap(u32),            // func → alloc count
    func_frees: std.StringHashMap(u32),             // func → free count
    ptr_to_func: std.AutoHashMap(u64, []const u8),  // ptr → holder func
};
```

**FuzzyMatcher** ([src/semantics/memory\_graph.zig](src/semantics/memory_graph.zig)):

```zig
pub fn isMatchingAllocFreePair(alloc_fn: []const u8, free_fn: []const u8) bool {
    // 检查库前缀是否匹配
    const alloc_prefix = extractLibPrefix(alloc_fn);
    const free_prefix = extractLibPrefix(free_fn);
    if (!std.mem.eql(u8, alloc_prefix, free_prefix)) return false;

    // 检查后缀是否匹配: malloc↔free, new↔delete, init↔cleanup, etc.
    if (std.mem.endsWith(u8, toLower(alloc_fn), "malloc") and
        std.mem.endsWith(u8, toLower(free_fn), "free")) return true;
    // ... more patterns
}
```

### 3.3 跨函数验证逻辑

```zig
pub fn resolveFreeValidation(self: *CrossFunctionAnalyzer, free_func: []const u8, ptr_value: u64) CrossFunctionResult {
    // 1. 检查 ptr 是否来自已知 alloc
    const ptr_origin = self.relations.getPtrOrigin(ptr_value);
    if (ptr_origin) |origin| {
        if (FuzzyMatcher.isMatchingAllocFreePair(origin.alloc_func, free_func)) {
            return .{ .is_valid = true, .reason = "fuzzy_matched", .confidence = 0.85 };
        }
    }

    // 2. 检查 ptr 所在函数是否调用过 alloc
    const ptr_holder = self.relations.getPtrHolderFunc(ptr_value);
    if (ptr_holder) |holder_func| {
        const alloc_count = self.relations.getFuncAllocCount(holder_func);
        if (alloc_count > 0) {
            return .{ .is_valid = true, .reason = "ptr_from_alloc_in_same_func", .confidence = 0.95 };
        }

        // 3. 检查调用链中是否有 alloc
        if (self.hasAllocInCalleeChain(holder_func)) {
            return .{ .is_valid = true, .reason = "ptr_from_callee_chain", .confidence = 0.75 };
        }
    }

    return .{ .is_valid = false, .reason = "unknown_origin", .confidence = 0.5 };
}
```

## 六、主要问题分析

### 6.1 borrow\_escape 误报 (占比 18.5%)

**问题**: C API 的"输出参数"模式被误报为悬空指针

**典型案例**: `sqlite3_malloc`, `sqlite3_mutex_alloc`, `sqlite3_column_blob`

```c
// 完全合法的 C API - 被误报
void *sqlite3_malloc(u64 n) {
    return malloc(n);  // 堆分配!
}
```

**根本原因**: PtrLifetimePass 未正确追踪 `ret` 指令的实际来源

### 6.2 invalid\_free 误报 (占比 23.7%)

**问题**: 自定义内存分配器被误报

**典型案例**: `__rustc_dealloc`, `OPENSSL_free`

这些是 Rust/BoringSSL 的自定义释放函数，与标准 `free()` 不同。

### 6.3 double\_free 可能过度检测

**观察**: sqlite3 (225), curl8 (66)

**原因**: "X malloc vs Y free" 模式未正确关联
