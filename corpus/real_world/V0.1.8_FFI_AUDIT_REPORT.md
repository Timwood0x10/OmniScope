# OmniScope v0.1.8 — FFI/Unsafe 边界安全审计报告

> **定位**: OmniScope 是 **FFI/Unsafe 边界安全静态分析工具**
> **核心能力**: 检测跨语言调用 (C/Rust/Zig/Go ↔ C) 的内存安全、生命周期、资源管理问题
> **版本**: v0.1.8 | **日期**: 2026-04-29
> **重大更新**: PtrLifetimePass IR级生命周期分析 + C++ 析构函数/构造函数过滤

---

## 一、v0.1.8 核心架构变更

### 1.1 生命周期分析：从启发式 → IR级

**v0.1.7 方案**: 函数名模式匹配 (`inferLifetimeConstraints`)
- 基于启发式函数名列表（ctime, strchr, getenv 等）
- 准确率有限，无法处理复杂场景

**v0.1.8 方案**: PtrLifetimePass IR级 def-use chain 分析
- 基于 LLVM IR 指令级追踪（alloca, load, store, call）
- 追踪指针分配点（stack/heap）、是否逃逸、是否释放
- **新增**: C++ 析构函数/构造函数过滤（避免 `this` 指针返回误报）

### 1.2 删除的启发式函数

以下启发式函数已被 PtrLifetimePass 完全替代并删除：
- `inferLifetimeConstraints()` - 生命周期约束推断
- `inferReturnValueLifetime()` - 返回值生命周期分类
- `checkDanglingPointerPatterns()` - 悬空指针模式检测
- `validateParameterLifetime()` - 参数生命周期验证
- `isWriteOperation()` - 写操作判断
- `isNullableParameter()` - NULL 参数判断

### 1.3 C++ 析构函数/构造函数过滤

新增 `isCppDestructorOrConstructor()` 函数，过滤 C++ mangled name 中的：
- `C1E` / `C2E` - 构造函数
- `D1E` / `D2E` - 析构函数

这些函数返回 `this` 指针是正常模式，不是 bug。

## 三、PtrLifetimePass 问题分析

### 3.1 Borrow Escape 误报根因

**问题模式**:
```c
// C API 模式 - 误报
int sqlite3_status64(int op, int *pCurrent, int *pHighwater, int resetFlag) {
    int local_var;
    // ... 使用 pCurrent, pHighwater 存储结果 ...
    return 0;
}
```

**IR 模式**:
```llvm
entry:
  %pCurrent.addr = alloca ptr          ; 栈上存储指针参数地址
  store ptr %pCurrent, ptr %pCurrent.addr
  ; ... 使用 %pCurrent.addr ...
  ret i32 0                            ; 返回值是 i32，不是 ptr
```

**误报原因**: PtrLifetimePass 没有正确区分：
1. 返回 `alloca` 的地址（真 bug）
2. 使用 `alloca` 存储输入指针（正常模式）
3. 返回值是 non-pointer 类型（正常）

### 3.2 准确率统计

| 项目 | 真阳性 (TP) | 假阳性 (FP) | 精确率 |
|------|-------------|-------------|--------|
| sqlite3 | ~587 | ~1,570 | 27% |
| curl8 | ~192 | ~506 | 28% |
| libuv150 | ~177 | ~315 | 36% |
| wasmtime_test | ~385 | ~22 | **95%** |

**结论**: PtrLifetimePass 在 Rust 项目（wasmtime_test）上准确率高达 95%，但在 C 项目上因 C API 模式导致准确率较低（27-36%）。

## 十、技术架构

### 10.1 PtrLifetimePass 核心数据结构

```zig
// 指针分配点分类
pub const PtrAllocSite = enum(u8) {
    heap,      // malloc/calloc/realloc
    stack,     // alloca 指令
    parameter, // 函数参数
    global,    // 全局变量
    constant,  // 常量/null
    unknown,   // 未知来源
};

// C++ 析构函数/构造函数过滤
fn isCppDestructorOrConstructor(func_name: []const u8) bool {
    if (func_name.len == 0) return false;
    if (func_name[func_name.len - 1] == 'E') {
        if (std.mem.indexOf(u8, func_name, "C1E") != null or
            std.mem.indexOf(u8, func_name, "C2E") != null or
            std.mem.indexOf(u8, func_name, "D1E") != null or
            std.mem.indexOf(u8, func_name, "D2E") != null)
        {
            return true;
        }
    }
    return false;
}
```
